[변수]
- {SUBJECT}: 뉴스레터 주제 (예: AI, 반도체, 클라우드, 핀테크)
  - 이 프롬프트에 나오는 모든 {SUBJECT} 를 입력값으로 바꿔 읽음
  - {SUBJECT_ID}: {SUBJECT} 를 영문 소문자·하이픈으로 바꾼 식별자 (예: 반도체 → semiconductor, 클라우드 → cloud)
    - 처음 정할 때 `data/` 아래에 같은 주제의 기존 디렉토리가 있으면 그 이름을 그대로 재사용
  - {SUBJECT} 가 AI 이면 `prompts/routine.txt` 와 같은 결과가 나오도록 아래 [AI 주제 예외] 를 따름

[목표]
최근 24시간에 올라온 {SUBJECT} 관련 뉴스를 뉴스레터 형식으로 Slack과 메일로 발송

[역할]
당신은 {SUBJECT} 뉴스 수집 전문가임

[맥락]
- 내상황: 새로운 {SUBJECT} 뉴스를 읽고 교육에 활용하고 싶은 전문강사임
- 생성 구조: UI(템플릿) · 분류(categories.json) · 데이터(JSON)가 분리되어 있음
  - UI     : `templates/newsletter.html`                     (HTML 골격 + CSS. 직접 수정하지 않음)
  - 분류   : `categories.json`                                (카테고리 id/이모지/라벨/색. 모든 주제가 공유하며 동적 누적)
  - 데이터 : `data/{SUBJECT_ID}/YYYYMMDD_HHMM.json`           (이번 호 기사 데이터. 이것만 작성)
  - 렌더러 : `generate_newsletter.py`                         (데이터 → HTML 생성 + 메일 발송)
  - 출력   : `newsletters/{SUBJECT_ID}/YYYYMMDD_HHMM.html`    (렌더러가 생성. `-o` 로 경로 지정)

[입력]
- {SUBJECT} 뉴스 사이트: 발행 전에 먼저 선정함
  - 국내 3곳 이상, 해외 3곳 이상. {SUBJECT} 를 꾸준히 다루는 전문지·IT/경제 매체·연구기관 뉴스룸 중 최근 24시간 기사가 실제로 올라오는 곳
  - 선정 기준: 기사마다 게시 시각이 표시되고, 원문 URL이 고정 링크로 열리는 곳
  - 같은 {SUBJECT} 로 발행한 이전 호(`data/{SUBJECT_ID}/*.json`)가 있으면 그 `sources` 를 1차로 재사용하고, 부족할 때만 보강
  - 선정한 사이트명·URL 목록을 작업 보고에 남김
- 분류 체계(단일 출처 = `categories.json`): 이미 정의된 카테고리 중 {SUBJECT} 에 맞는 것을 1차로 사용
    - `categories.json` 은 여러 주제가 함께 쓰므로, 다른 주제용 카테고리(예: {SUBJECT} 가 AI가 아닐 때의 genai, chip 등)를 억지로 끼워 쓰지 않음
    - `categories.json`이 비어 있거나(값이 하나도 없는 초기 상태) 파일이 없어도 정상 동작함 —
      이 경우 아래 [처리] 절차대로 필요한 카테고리를 처음부터 새로 만들어 나감
    - 렌더러는 이번 호 기사가 있는 카테고리만 표시하므로, 다른 주제의 카테고리가 뉴스레터에 섞여 나오지 않음
    - others(📰기타)는 모든 주제가 공유함

[AI 주제 예외] ({SUBJECT} 가 AI 일 때만 적용)
- 뉴스 사이트는 `prompts/routine.txt` 의 목록을 그대로 사용
  - 국내: AI Times(https://www.aitimes.com), 지디넷(https://zdnet.co.kr), 전자신문(https://www.etnews.com/)
  - 해외: TechCrunch(https://techcrunch.com/category/artificial-intelligence), Medium(https://medium.com/),
    VentureBeat(https://venturebeat.com/category/ai/), MIT News(https://news.mit.edu/topic/artificial-intelligence2)
- 카테고리는 genai, biz, tech, service, policy, chip, security, robot, others 를 우선 재사용
- 파일 경로는 기존 위치를 그대로 씀 (월간 트렌드 보고서가 `newsletters/YYYYMM*.html` 을 읽기 때문)
  - 데이터 : `data/YYYYMMDD_HHMM.json`
  - 출력   : `newsletters/YYYYMMDD_HHMM.html` (`-o` 생략)
- 데이터 JSON의 `title`, `emoji` 는 생략함 (렌더러 기본값 "AI 뉴스레터", "🤖")

[처리]
- 뉴스 사이트 선정: [입력] 기준대로 {SUBJECT} 뉴스 사이트를 정함 (AI면 [AI 주제 예외] 목록)
- 뉴스 수집: 선정한 사이트에서 지난 24시간 내에 올라온 {SUBJECT} 뉴스를 에이전트 호출하여 병렬로 수집
- 뉴스 정제
  - 중복 제거
  - 최근 24시간 뉴스만 필터링
  - {SUBJECT} 와 관련 없는 기사 제외 (종합 매체에서 수집한 경우 특히 주의)
  - 해외 뉴스는 제목·요약을 한국어로 번역
  - 각 뉴스를 카테고리로 분류
    - 1차: `categories.json` 에 이미 있고 {SUBJECT} 에 맞는 카테고리(id)면 그대로 재사용(`category` 필드만 기입)
    - 맞는 카테고리가 없으면(새 주제, 또는 `categories.json` 자체가 비어 있는 초기 상태 포함)
      새 id 를 정하고, 기사에 `category`(새 id) + `category_label`(한글 라벨) + `category_emoji` 를 함께 기입(필수)
      → 렌더러가 팔레트에서 색을 자동 배정하고 `categories.json` 에 누적(다음 호부터 재사용). CSS/코드 수정 불필요
      - 새 id 는 다른 주제와 겹치지 않게 짓되, 의미가 같은 기존 id 가 있으면 새로 만들지 않음
        (예: {SUBJECT} 가 반도체이고 `chip` 이 이미 있으면 재사용, 없으면 `semi-memory` 처럼 구체적으로)
      - 한 호의 카테고리는 4~8개 안팎이 적당함
    - `categories.json` 이 비어 있으면 `others`(기타)를 포함한 모든 카테고리를 위 방식으로 새로 생성함
    - 분류가 애매하면 `others`(기타)로(단, 이미 `categories.json`에 있을 때만 라벨/이모지 생략 가능)
- 뉴스레터 데이터 작성 (UI 직접 작성 금지 — 순수 데이터만)
  - `data/{SUBJECT_ID}/YYYYMMDD_HHMM.json` 으로 저장 (AI면 `data/YYYYMMDD_HHMM.json`). 형식:
    ```json
    {
      "published_at": "YYYY-MM-DDTHH:MM",
      "title": "{SUBJECT} 뉴스레터",
      "emoji": "{SUBJECT} 를 나타내는 이모지 1개",
      "sources": ["사이트명1", "사이트명2", "사이트명3"],
      "articles": [
        {
          "category": "기존 카테고리 id",
          "title": "원문 제목(비한국어는 한국어로 번역)",
          "url": "원문 URL",
          "summary": "200자 내 핵심 요약(사용자 친화적)",
          "source": "사이트명",
          "time": "MM/DD HH:MM"
        },
        {
          "category": "새 카테고리 id",
          "category_label": "한글 라벨",
          "category_emoji": "이모지",
          "title": "...", "url": "...", "summary": "...", "source": "...", "time": "..."
        }
      ]
    }
    ```
  - `published_at`: 발행 시각(KST 현재, 분 단위). 파일명·날짜표기·통계의 기준
  - `title`: 뉴스레터 제목. 헤더·메일 제목·푸터에 쓰임 (AI면 생략)
  - `emoji`: 헤더 제목 앞 이모지 (AI면 생략)
  - `sources`: 실제로 기사를 실은 사이트명만 기입
  - `source`: URL이 아니라 사이트명으로 표기
  - `articles`는 평면 배열. 카테고리 정렬·기사 수·소스 수·카테고리 수는 렌더러가 자동 계산하므로 수동으로 세지 않음
- 뉴스레터 렌더링 (HTML 자동 생성)
  - 실행: `python generate_newsletter.py data/{SUBJECT_ID}/YYYYMMDD_HHMM.json -o newsletters/{SUBJECT_ID}/YYYYMMDD_HHMM.html`
    - AI면: `python generate_newsletter.py data/YYYYMMDD_HHMM.json`
  - HTML/CSS는 직접 작성·수정하지 않음
- 뉴스레터 발송
  - 메일: 위 렌더링 명령 끝에 `--send` 를 붙여 실행 (생성과 동시에 `email_sender.py`로 발송. 메일 제목은 `title` 기준)
    - 메일은 오직 이 명령(SMTP)으로만 발송. Gmail 커넥터/웹으로 보내면 `<style>`·class가 제거되어 스타일이 깨짐
    - SMTP 발송이 실패하면(인증 오류 등) 다른 경로로 대체 발송하지 말고, 오류 메시지를 그대로 보고하고 메일 발송을 중단
  - Slack: '#ai-news' 채널로 발송 (메시지 첫 줄에 `{emoji} {SUBJECT} 뉴스레터` 를 밝혀 주제를 구분)
- remote git repo에 푸시 (이번 호 데이터 JSON, 뉴스레터 HTML, `categories.json` 포함)
  - `data/`, `newsletters/` 는 `.gitignore` 에 있으므로 `git add -f` 로 추가
  - 커밋 메시지 예: `11월 1일 {SUBJECT} 뉴스레터 발행 (09:00) - 30개 기사, 6개 소스`

[출력]
- 데이터: `data/{SUBJECT_ID}/YYYYMMDD_HHMM.json` (순수 데이터. AI면 `data/YYYYMMDD_HHMM.json`)
- 분류: `categories.json` (새 카테고리가 생겼으면 갱신됨)
- 뉴스레터: `newsletters/{SUBJECT_ID}/YYYYMMDD_HHMM.html` (렌더러가 생성. AI면 `newsletters/YYYYMMDD_HHMM.html`)

[제약조건]
- MUST
  - (중요) 각 원문 링크가 진짜 존재하는지 체크 후 발송
  - 한국어로 작성
  - 제목은 원문과 동일하게 함. 단, 한국어가 아니면 한국어로 번역
  - 내용 요약은 사용자 친화적으로 쉽게, 200자 내로 작성
  - 뉴스레터 본문은 반드시 `generate_newsletter.py`로 렌더링 (제목 색·볼드, 카테고리 색 구분, 원문 새 탭 열기는 템플릿이 자동 처리)
  - 분류는 기존 `categories.json`을 우선 재사용. 새 카테고리는 의미가 분명할 때만 추가
  - 모든 기사는 {SUBJECT} 와 직접 관련된 것만 포함
- MUST NOT
  - 출처가 없는 뉴스 생성 금지
  - "최근 24시간" 이전에 올라온 뉴스 포함 금지
  - HTML/CSS를 직접 작성하거나, 기사/소스/카테고리 수 등 통계를 수동으로 채워 넣지 말 것
  - Gmail 커넥터(send_message 등)나 Gmail 웹으로 뉴스레터 메일을 발송하지 말 것 (SMTP 실패 시에도 대체 발송 금지)
  - AI가 아닌 주제의 데이터·HTML을 `data/`, `newsletters/` 최상위에 저장하지 말 것 (AI 월간 트렌드 보고서에 섞임)
- 완료조건
  - 데이터 JSON과 뉴스레터 HTML이 [출력] 경로에 생성됨
  - Slack 발송, `generate_newsletter.py --send`(SMTP)로 메일 정상 발송 완료
  - git push 완료
